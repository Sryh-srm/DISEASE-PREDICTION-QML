# COMPLETE BACKEND AUDIT REPORT

## PART 1 — REPOSITORY STRUCTURE

### A. Backend

* **backend/** - Contains the core FastAPI application and ML components
  * **app.py** - Main FastAPI application entry point with prediction endpoints, model loading, and API routes
  * **preprocess.py** - Data preprocessing pipeline handling imputation, scaling, supervised ANOVA feature selection (top 4 features), and rescaling to [0, π] for quantum angle encoding
  * **quantum_model.py** - Implementation of quantum machine learning models: Variational Quantum Classifier (VQC), Quantum Ensemble (bagged VQCs), and Quantum Kernel Classifier (projective quantum kernel SVM)
  * **train.py** - Complete training script that downloads data, preprocesses, trains quantum and classical models, builds stacked hybrid committee, evaluates performance, and saves artifacts
  * **artifacts/** - Directory containing all saved model artifacts:
    * **preprocessor.pkl** - Fitted preprocessing pipeline (imputer, scaler, selector, angle scaler)
    * **vqc_model.pkl** - Trained standalone Variational Quantum Classifier
    * **ensemble_model.pkl** - Trained bagged VQC ensemble (5 members)
    * **qkernel_model.pkl** - Trained quantum kernel SVM with CV-tuned regularization parameter C
    * **committee.pkl** - Stacked hybrid committee bundle (member names, meta-learner coefficients, tuned threshold)
    * **classical_members.pkl** - Tuned classical SVM and Logistic Regression models for the committee
    * **feature_importance.json** - Feature importance data for UI explainability (from Random Forest on selected features)
    * **vqc_metrics.pkl** - Backward compatibility file containing VQC test metrics

### B. Existing QML Frontend

* **frontend/** - Contains the legacy QML user interface
  * **main.qml** - Main application window composing PatientForm, ResultDisplay, and HistoryList components
  * **PatientForm.qml** - Patient data entry form with all 13 clinical features (age, sex, cp, trestbps, chol, fbs, restecg, thalach, exang, oldpeak, slope, ca, thal)
  * **ResultDisplay.qml** - Component showing prediction probability, risk level (Low/Moderate/High), recommendation, and feature importance bars
  * **HistoryList.qml** - Component displaying recent prediction history
  * **run_ui.py** - Launcher script that starts the FastAPI backend (if not running) and opens the QML UI

**QML ↔ Python Communication**: The frontend communicates exclusively with the backend via HTTP requests to FastAPI endpoints:
  * `/predict` - Single patient prediction (POST with JSON patient data)
  * `/predict/csv` - Batch scoring (POST with CSV file upload)
  * `/feature_importance` - GET request to fetch feature importance data for explainability
  * `/health` - GET request to check backend status

1. Loads preprocessing pipeline from `backend/artifacts/preprocessor.pkl`
2. Loads standalone VQC model from `backend/artifacts/vqc_model.pkl`
3. Attempts to load stacked hybrid committee artifacts:
   - Checks for existence of all required artifacts (COMMITTEE_PATH, ENSEMBLE_PATH, QKERNEL_PATH, CLASSICAL_MEMBERS_PATH)

   - Loads classical SVM and Logistic Regression models

## PART 3 — COMPLETE DATA FLOW

**Data Flow Through Backend:**

1. **Input Entry**
   - Single prediction: JSON payload via `/predict` endpoint validated by `PatientData` Pydantic model
   - Batch prediction: CSV file upload via `/predict/csv` endpoint

2. **Validation**
   - Single: Pydantic validates data types and ranges (age 0-120, sex 0-1, etc.)
   - Batch: Checks for required columns (`FEATURES` list) and non-empty DataFrame
   - Both: HTTP 400 errors for validation failures with descriptive messages

3. **Preprocessing** (`_score_frame` → `transform_preprocessor`)
   - Selects only the 13 `FEATURES` columns
   - Applies fitted preprocessing pipeline (loaded during startup):
     * `SimpleImputer(strategy="median")` - fills missing values with column median
     * `StandardScaler()` - zero mean, unit variance scaling
     * `SelectKBest(score_func=f_classif, k=4)` - supervised ANOVA selects top 4 features
     * `MinMaxScaler(feature_range=(0.0, np.pi))` - rescales to [0, π] for quantum angle encoding
   - Output: numpy array of shape `(n_samples, 4)` containing the selected, transformed features

4. **Feature Engineering/Selection**
   - Performed by `SelectKBest` with `f_classif` (ANOVA F-value) during preprocessing fitting
   - Selected features stored in preprocessing pipeline and retrievable via `selected_feature_indices()`
   - Currently selects: `["thal", "thalach", "ca", "exang"]` (as seen in feature_importance.json)

5. **Scaling/Normalization**
   - Two-stage scaling in pipeline:
     * StandardScaler: zero mean, unit variance
     * MinMaxScaler to [0, π]: prepares data for quantum angle embedding (multiplied by π inside quantum circuits)

6. **Feature Encoding**
   - Classical features → quantum angle encoding via `RY(π * scaled_feature)` in quantum circuits
   - Handled in `quantum_model.py`:
     * `QuantumModel.circuit`: `qml.AngleEmbedding(np.pi * input_scales * X, wires=range(self.n_qubits), rotation="Y")`
     * `QuantumKernelClassifier.feature_map`: Same angle embedding for quantum kernel computation

7. **Model Inference**
   - Depends on model availability:
     * **Primary** (if committee loaded): `_committee_proba()` function
       1. Gets probability predictions from each committee member:
          - Quantum Kernel SVM (`qkernel.predict_proba(X)[:, 1]`)
          - VQC Ensemble (`ensemble.predict_proba(X)[:, 1]`)
          - Standalone VQC (`model.predict_proba(X)[:, 1]`)
          - Classical SVM (`members["svm"].predict_proba(X)[:, 1]`)
          - Classical Logistic Regression (`members["lr"].predict_proba(X)[:, 1]`)
       2. Stacks probabilities into columns: `[p_qkernel, p_ensemble, p_vqc, p_svm, p_lr]`
       3. Applies meta-learner LogisticRegressionStub to get final probability
     * **Fallback** (if committee missing): Uses standalone VQC directly
       * `model.predict_proba(X)[:, 1]`

8. **Post-processing**
   - Converts raw probability to risk level using `_risk_level()`:
     * Calculates risk bands: `moderate_low = 0.6 * threshold`, `high = min(1.4 * threshold, 0.95)`
     * "Low" if prob < moderate_low
     * "Moderate" if moderate_low ≤ prob < high
     - "High" if prob ≥ high
   - Generates recommendation using `_recommendation()` based on same thresholds
   - For batch predictions: applies same logic to each row

9. **Final Output**
   - Returns JSON response with:
     * `probability`: float (final prediction probability for class 1/disease)
     * `risk`: string ("Low"/"Moderate"/"High")
     * `recommendation`: string (clinical advice)
     * `threshold`: float (decision threshold used)
     * `model`: string (identifier: "hybrid-quantum-committee (stacked)" or "vqc")

## PART 5 — QML / PENNYLANE

### Quantum Configuration

* **Number of qubits**: 4 (hardcoded in `QuantumModel.__init__` default `n_qubits=4`, used throughout)
* **Number of classical input features**: 4 (after preprocessing feature selection - matches qubit count)
* **Quantum device**: `"default.qubit"` (PennyLane's built-in pure Python simulator)
* **Simulator/hardware**: Software simulator only (no hardware backend specified or used)
* **Shots**: Not specified (defaults to None → exact expectation values, not sampling)
* **Device configuration**: Standard `default.qubit` device with 4 wires

### Feature Encoding

* **Encoding method**: Angle embedding using `RY(π * scaled_feature)` rotations
* **Gates used**:
  * Primary encoding: `RY` gates
  * Additional encoding: `RZ` gates with constant offset (see quantum_model.py lines 76-80)
  * Trainable rotations: `Rot` gates (combined RX-RY-RZ)
  * Entanglement: `CNOT` gates in ring topology
* **Mapping between classical features and quantum gates**:
  * Feature 0 → qubit 0 `RY` gate
  * Feature 1 → qubit 1 `RY` gate
  * Feature 2 → qubit 2 `RY` gate
  * Feature 3 → qubit 3 `RY` gate
  * (Direct 1:1 mapping after feature selection)
* **Input ranges**: Features scaled to [0, 1] by preprocessing, then multiplied by π → [0, π]
* **Scaling/normalization before encoding**:
  * StandardScaler (zero mean, unit variance)
  * MinMaxScaler to [0, 1]
  * Final multiplication by π in quantum circuits → [0, π]

### Circuit

* **Circuit structure**:
  * Repeated `layers` times (default 4):
    1. Encoding block: `RY(π * s_k * x_k)` then `RZ(s_k)` on each qubit
    2. Trainable block: `StronglyEntanglingLayers` (Rot gates + CNOT ring)
  * Data re-uploading: Input features re-encoded at the start of each layer
* **Gates**:
  * Single-qubit: `RY`, `RZ`, `Rot` (which decomposes to RX-RY-RZ)
  * Two-qubit: `CNOT` (nearest-neighbor ring connectivity)
* **Ansatz**: `StronglyEntanglingLayers` ansatz with data re-uploading
* **Ansatz depth**: Equal to `layers` parameter (default 4)
* **Entanglement topology**: Ring (each qubit i connected to (i+1) mod n_qubits via CNOT)
* **Parameterized gates**:
  * `Rot` gates: 3 parameters per qubit per layer → total `(layers × n_qubits × 3)`
  * Input scales: `n_qubits` parameters (if `input_scales=True`)
  * Readout weights: `n_qubits` parameters
  * Bias: 1 parameter
* **Measurements**:
  * Measures `⟨Z_k⟩` (PauliZ expectation) on each qubit k
  * Returns list of expectation values, one per qubit
* **Observables**: PauliZ operators on individual qubits (no multi-qubit observables)

### Training

* **Dataset**: Preprocessed training data (after train/test split)
* **Loss Function**: Mean squared error between predictions (±1 target) and `y_target = 2*y - 1` (maps 0/1 to -1/+1)
* **Optimizer**: Adam optimizer with cosine learning rate annealing
* **Learning rate**:
  * Initial: 0.15 (default in `QuantumModel.__init__`)
  * Schedule: Cosine annealing from learning_rate down to 1% of it over epochs
* **Epochs/iterations**: 120 (default in `QuantumModel.__init__` and `train.py`)
* **Trainable parameters**:
  * Weights: `(layers, n_qubits, 3)`
  * Out weights: `(n_qubits,)`
  * Bias: 1
  * Scales: `(n_qubits,)` (if `input_scales=True`)
  * Total: `(4×4×3) + 4 + 1 + 4 = 57` trainable parameters for default config
* **Training procedure**:
  * Full-batch training (no mini-batches)
  * Gradient computed via PennyLane's autograd/backprop
  * Parameter updates via AdamOptimizer
  * Verbose logging every epoch//6 epochs showing loss and training accuracy
* **Saved trained parameters/model**:
  * Saved via `save_model()` method to pickle files
  * Contains: n_qubits, layers, device, weights, out_weights, bias, scales

### Inference

* **How inference is invoked**:
  * Through `predict_proba()` method which calls `_raw_predictions()` then maps to [0,1]
  * `_raw_predictions()`:
    1. Executes quantum circuit with current parameters to get `⟨Z_k⟩` expectations
    2. Combines expectations: `stacked @ out_weights + bias`
    3. Maps from [-1,1] to [0,1] via `(raw + 1)/2` with clipping
* **Input required**: Preprocessed features (4-dimensional after selection and scaling)
* **Output produced**:
  * `predict()`: Binary class predictions (0 or 1)
  * `predict_proba()`: Probability array `[prob_class_0, prob_class_1]`
* **Post-processing**:
  * In quantum models: maps raw expectation values ([-1,1] range) to probabilities ([0,1])
  * In API: applies risk bands and recommendations based on threshold
* **Classification/risk calculation**:
  * Binary threshold at probability 0.5 for class prediction
  * Risk levels based on tuned threshold (Low/Moderate/High bands)

### Noise/error mitigation

* **Noise models**: **NOT IMPLEMENTED** - uses ideal `default.qubit` simulator
* **ZNE (Zero Noise Extrapolation)**: **NOT IMPLEMENTED**
* **Error mitigation**: **NOT IMPLEMENTED**
* **Any other mitigation technique**: **NOT IMPLEMENTED**
* **Assessment**: All quantum modeling assumes perfect, noise-free simulation

## PART 14 — BACKEND INTEGRATION RISKS

* **BLOCKING**:
  * **Missing API endpoints for individual model predictions**: If React needs to show/explain individual quantum model contributions, backend does not expose these
  * **Missing quantum explainability**: If React expects quantum-specific attribution (e.g., quantum Shapley values), backend only provides classical RF importance

* **IMPORTANT**:
  * **Hardcoded feature selection**: Backend always selects exactly 4 features via ANOVA; React cannot change this without modifying preprocessing
  * **Fixed quantum circuit architecture**: Number of qubits (4), layers (4), and ansatz are hardcoded; changes require code modification
  * **Threshold calculation method**: Uses Youden's J on OOF predictions; React cannot influence this without retraining

* **MINOR**:
  * **Batch processing lacks progress feedback**: Long batch jobs show no intermediate progress to UI
  * **Limited model transparency**: API returns only "hybrid-quantum-committee (stacked)" or "vqc" without detail on member weights/contributions
  * **Single threshold for risk bands**: Uses fixed multipliers (0.6× and 1.4×) of threshold; cannot customize band widths per use case
  * **CPU-only inference**: No GPU acceleration option for quantum simulations (may be slow for large batches)
